# 解法：不统一"驱动"，统一"状态 + 指令"

## 一、问题

本整合包里驱动一辆车的方式至少有这么几类（均有代码依据）：

| 驱动 | 输出的是 | 注入点 |
|---|---|---|
| Create 传动轴 → 转向架 | **转速**（rad/tick） | 轮轨接触 |
| Portable Engine（simulated） | 燃料 → 力 | 刚体 |
| 推进器（ForceGroups.PROPULSION） | **力** | 刚体 |
| 气球/浮力（BALLOON_LIFT / LEVITATION） | **力** | 刚体 |
| 磁力（MAGNETIC_FORCE） | **力** | 刚体 |
| 帆（SymmetricSail） | 风 → 力 | 刚体 |
| 运动学体（Create contraption） | **直接位姿** | 无 |

它们的**物理量种类不同**（转速 / 力 / 冲量 / 位姿）、**注入点不同**、
还能**互相叠加**。所以不存在一个"统一速度公式"能涵盖全部。

## 二、转向：不要建模驱动，要记录响应

关键判断：

> **驱动方式千差万别，但它们在"沿轨道方向"上的结果只有一个——加速度。**

所以：

    统一的是：状态（s, v）+ 指令（u）
    不统一的是：驱动本身

### 状态

    s  —— 沿轨里程
    v  —— 沿轨速度（标量，可负）
    m  —— 质量（用于换算，可选）

### 指令

    u ∈ [-1, 1]    由调度器自己的通道给出
                   左岔道 / 右岔道 / 刹车，本来就是我们控制的

## 三、在场时：观测响应，写成表

每 tick（或每 N tick）：

    v_obs      = 姿态差分速度 · 轨道切线
    a_obs      = (v_obs - v_obs_prev) / dt
    a_grade    = -g · sin(坡度)                  // 从轨道几何算
    a_drive    = a_obs - a_grade                 // 扣掉重力分量

    table[v 分桶][u 分桶] ← 滑动平均(a_drive)

表的大小：

    v 分桶：20 段（每 1 m/s 一格，覆盖 0~20 m/s）
    u 分桶：9 段（-1, -0.75, ... , 1）
    → 180 个 double，每车一份，可存 NBT

## 四、不在场时：用表积分

    a = table[v][u] + a_grade
    v += a · dt
    s += v · dt

坡度分量单独算，`table` 里只保留"驱动本身的响应"，
这样同一张表在任何线路上都能用。

## 五、为什么这能解决"千差万别"

因为我们**从不判断用的是什么驱动**：

- 转轴驱动的车 → 表里记录的是"红石给满速时，沿轨加速度是多少"
- 推进器的车 → 表里记录的也是"推进器开着时，沿轨加速度是多少"
- 帆船 → 同理

**它们在我们的模型里全都退化成同一个东西：一张 (v, u) → a 的表。**

## 六、需要处理的边界

| 情况 | 处理 |
|---|---|
| 表为空（新车） | 用最后一次观测到的 a，按指数衰减 |
| 表没覆盖到的桶 | 双线性插值 / 最近邻 |
| 饱和（推不动） | 表自然记录为 0，不需要特判 |
| 溜车（u=0 且有坡） | `a_grade` 会给出正确的下滑加速 |
| 转弯限速 | 由调度器另算，不放进表里 |
| 碰撞 | **无解**，出范围时不存在碰撞，接受这个近似 |
| 多种驱动叠加 | 不需要区分，观测的就是合力效果 |

## 七、与铁律的关系

这不违反〇之二（物理体权威）：

- **在场时**：物理体是权威，表只是"旁听记录"
- **不在场时**：表是从物理体身上学来的，等于物理体的代理，而不是另造一套假物理
- 指令 `u` 始终由调度器发出，符合〇之三（控制器，不是动力源）

## 八、未解决的真实难点

1. **表是"这辆车"的经验**：换车厢、加减载重后需要重新学习（可以按质量缩放）
2. **坡度必须算准**：Create 的 `TrackEdge` 能否给出准确坡度，需要验证
3. **低速时噪声大**：`a_obs` 由速度差分而来，v 很小时误差会被放大，需要低通滤波
